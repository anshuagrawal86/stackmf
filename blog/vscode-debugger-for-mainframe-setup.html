Step-by-Step Configuration of the VS Code Debugger for Mainframe with IBM z/OS Debugger

StackMF Mainframe Architecture Pod
Principal Modernization & z/OS Systems Engineers
Verified Production Fix
Executive Summary / TL;DR

Bring modern visual debugging to VS Code. Learn how to configure launch.json, connect to the IBM z/OS Debugger headless service, and execute interactive source-level breakpoint debugging inside Visual Studio Code.

1 The Real-World Developer Incident

Developers who have migrated to VS Code for code editing are still forced to switch to terminal sessions or 3270 green-screens whenever they need to debug a COBOL program step-by-step.

2 Technical Root Cause & Architecture Mechanics

The IBM Z Open Debug extension enables the VS Code Debug Adapter Protocol (DAP) to communicate with the IBM z/OS Debugger on the mainframe over TCP/IP.

3 Step-by-Step Production Resolution

# 1. Install IBM Z Open Debug Extension

In VS Code, install IBM.zopeneditor and IBM.z-open-debug.

# 2. Configure .vscode/launch.json

Add the debug launch configuration:

json 
{
  "version": "0.2.0",
  "configurations": [
    {
      "type": "zopenedebug",
      "request": "launch",
      "name": "Debug Mainframe Batch COBOL",
      "port": 8001,
      "secure": false,
      "trace": true
    }
  ]
}

# 3. Launch Debug Session and Run Job

1. Press F5 in VS Code to start listening on port 8001.

2. Submit your batch JCL with //CEEOPTS DD pointing to your IP:

TEST(ALL,*,PROMPT,TCPIP&%8001:)

3. When the job runs on z/OS, VS Code pauses execution, highlights the first line in yellow, and allows you to set visual breakpoints in the gutter!

Architectural Prevention & Performance Tuning Checklist

  • Ensure workstation IP is reachable from the z/OS network (VPN/corporate LAN).
  • Store compiler side-files (`SYSDEBUG`) in accessible libraries.
  • Clean up completed debug sessions to release mainframe TCB threads.
