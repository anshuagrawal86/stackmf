Customizing Software Analyzer and Code Quality Rulesets in IDz for Enterprise COBOL Standards

StackMF Mainframe Architecture Pod
Principal Modernization & z/OS Systems Engineers
Verified Production Fix
Executive Summary / TL;DR

Enforce strict coding standards across your mainframe team. Configure IBM Developer for z/OS (IDz) Software Analyzer rulesets to automatically flag dangerous patterns like GOTO, hardcoded SQL credentials, and uninitialized packed decimals.

1 The Real-World Developer Incident

Legacy codebases accumulate technical debt, unhandled errors, and non-performant constructs (PERFORM ... THROUGH, un-indexed table searches). Code reviews are manual and inconsistent, allowing buggy patterns to slip into production.

2 Technical Root Cause & Architecture Mechanics

IDz includes the Software Analyzer engine, capable of static AST (Abstract Syntax Tree) analysis across COBOL, PL/I, and SQL.

By defining custom rulesets, organizations establish automated gates that warn or fail builds when code violates security or performance standards.

3 Step-by-Step Production Resolution

# 1. Create a Custom Enterprise Ruleset (ruleset.xml)

In IDz:

1. Navigate to Window → Preferences → Software Analyzer → Rules and Categories.

2. Select COBOL and create ruleset Enterprise-COBOL-Standard:

  • Flag all ALTER statements (Severe).
  • Flag GOTO statements jumping outside current paragraph (Error).
  • Require FILE STATUS check immediately following any READ or WRITE (Warning).
  • Flag unconstrained OCCURS DEPENDING ON (Warning).

# 2. Run Static Analysis in IDz

Right-click your source folder → Software Analysis → Run As → Enterprise-COBOL-Standard.

The Software Analyzer Results view displays all violations with direct navigation to the offending source line.

# 3. Export Ruleset for Headless CI/CD Scanning

Export rules to XML and run headless in your pipeline:

bash 
/usr/lpp/IBM/idz/bin/code-review.sh   -ruleFile ./config/ruleset.xml   -sourceDir ./src   -outputDir ./reports/code-review-report.html

Architectural Prevention & Performance Tuning Checklist

  • Integrate IDz Code Review into automated pull request checks in GitHub Actions.
  • Block PR merging if severe ruleset violations exist.
  • Update rulesets periodically to reflect modern Enterprise COBOL 6.x performance best practices.
